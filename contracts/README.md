# Контракты планирования закупок

Версия `0.1.0`, предварительная до получения данных партнёра и подтверждения формулы. Владелец назначается в `docs/tasks.md`.

- `planning-input.schema.json` — нормализованный вход одного расчёта по одному складу.
- `planning-result.schema.json` — результат расчёта с объяснимыми числовыми компонентами.
- `api.md` — минимальный пользовательский поток; HTTP-маршруты окончательно фиксируются после выбора стека.

Дата — ISO `YYYY-MM-DD`, количество — неотрицательное целое число в базовой единице товара, деньги — число в тенге. `customer_id` только обезличенный. `goods_in_transit` — уже заказанное количество, которое ещё не вошло в `current_stock`. `growth_forecast_pct` — предоставленный внешний прогноз прироста, не итог работы модели. `stockouts` задают интервалы `[start_date, end_date]` включительно.

Поля цены и 1С не превращаются автоматически в спрос. Входная цена сохраняется для совместимости с данными партнёра. Материальная ведомость 1С пока не включена в канонический контракт: её смысл и пересечение с продажами нужно согласовать до интеграции. Если входные данные неполны, адаптер возвращает ошибку валидации, а не подставляет нули молча.

Фикстура `fixtures/planning-input.sample.json` показывает форму данных. Её числовые значения синтетические и не являются примером фактического прогноза.
