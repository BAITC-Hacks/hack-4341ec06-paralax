# Контракты планирования закупок

Входная схема использует `document_id` вместо недоступного ID клиента, а цена необязательна. Версия 0.2.0 добавляет месячную историю с неизвестными значениями, ETA транзита, дату и источник остатка. Для импорта реальных Excel остаётся подтвердить охват складских остатков. Выходная схема расширена диагностикой модели и полями UI. Правила расчёта — в [prediction-design.md](../docs/prediction-design.md).

- `planning-input.schema.json` — нормализованный вход одного расчёта по одному складу.
- `planning-result.schema.json` — результат расчёта с объяснимыми числовыми компонентами и полями для таблицы UI (`name`, `category`, `supplier_name`, `data_source`). Дата и источник остатка необязательны: отсутствие надо показывать как неизвестное.
- `explanation.schema.json` — структурированное объяснение с отметкой OpenAI или резервного текста.
- `api.md` — действующий пользовательский поток и HTTP-маршруты.

Дата — ISO `YYYY-MM-DD`, количество — неотрицательное целое число в базовой единице товара, деньги — число в тенге. `document_id` — номер документа продажи; он не является ID клиента. `unit_price_kzt` можно не передавать. `goods_in_transit` во входе — всё ещё не поступившее количество; в факторах результата это количество за вычетом `excluded_late_transit` после горизонта расчёта. `growth_forecast_pct` — предоставленный внешний прогноз прироста, не итог работы модели. `stockouts` задают только подтверждённые интервалы `[start_date, end_date]` включительно; нулевой месячный остаток сам по себе не задаёт точный интервал.

Поля цены и 1С не превращаются автоматически в спрос. Входная цена сохраняется для совместимости с данными партнёра. Материальная ведомость 1С пока не включена в канонический контракт: её смысл и пересечение с продажами нужно согласовать до интеграции. Если входные данные неполны, адаптер возвращает ошибку валидации, а не подставляет нули молча.

Фикстуры в `fixtures/` показывают форму данных. Их числовые значения синтетические и не являются примером фактического прогноза. `planning-result.demo.json` — полноценный мок для разработки UI. TypeScript-типы в `frontend/src/types/planning.generated.ts` генерируются из этих JSON Schema командой `npm run types:generate` в `frontend/`; они не редактируются вручную.
