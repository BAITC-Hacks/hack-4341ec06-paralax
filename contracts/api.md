# Минимальный API-контракт

Статус: предварительный; пути можно адаптировать после выбора стека, семантика действий обязательна.

- `POST /api/planning-runs` принимает `PlanningInput`, валидирует ссылки на SKU и поставщиков, даты и уникальность ID, возвращает `PlanningResult` со статусом `draft`. Ошибки входа возвращают список полей и причины без частичного результата.
- `PATCH /api/planning-runs/{run_id}/recommendations/{sku}` принимает `{ "selected_quantity": integer >= 0 }`. Доступно только для `draft`; сохраняет ручную правку, не изменяя исходное `recommended_quantity`.
- `POST /api/planning-runs/{run_id}/approve` переводит черновик в `approved` только после явного действия пользователя. Повторное утверждение не создаёт новый заказ.
- `GET /api/planning-runs/{run_id}/export` возвращает CSV, сгруппированный или сортированный по `supplier_id`, со статусом и выбранным количеством. Экспорт не отправляет заказ поставщику.

Если MVP работает локально без HTTP, эти же операции должны быть представлены функциями и переходами состояния. Внешние идентификаторы и права доступа к реальным данным проектируются после решения по стеку и партнёрским данным.
