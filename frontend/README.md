# Интерфейс планирования закупок

React + TypeScript + Vite. Дизайн четырёх страниц взят из `feat/codex/ui` и подключён к актуальному FastAPI backend. Типы результата генерируются из `contracts/planning-result.schema.json`.

## Запуск

Из корня репозитория сначала запустите backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --reload
```

Во втором терминале:

```powershell
npm ci --prefix frontend
npm run dev --prefix frontend
```

Откройте `http://127.0.0.1:5173`. Vite перенаправляет `/api` на `http://127.0.0.1:8000`; переменная `VITE_API_BASE_URL` нужна только при раздельном размещении. Проверки: `npm run check --prefix frontend`.

## Сценарий

Выберите синтетический набор или IEK и нажмите «Рассчитать». Синтетический набор берётся из `GET /api/demo/planning-input` и проходит через настоящий `POST /api/planning-runs`. IEK вызывает `POST /api/iek/planning-runs`: backend читает заранее подготовленный `outputs/iek-planning-result.input.json` либо импортирует четыре локальные книги IEK при первом вызове. Первый импорт и расчёт могут занять около минуты.

После расчёта доступны поиск и фильтр, факторы и предупреждения по SKU, ручное изменение количества, явное утверждение и CSV. Кнопка объяснения сейчас возвращает резервный текст: адаптер OpenAI к HTTP ещё не подключён. Заказ поставщику не отправляется. ID текущего черновика хранится только в `sessionStorage`; сами данные хранятся в памяти backend и исчезают после его перезапуска.

Остаток IEK датирован 01.09.2026 и не восстановлен до даты расчёта. Охват складов, сценарные сроки поставки и страховой запас требуют проверки менеджером. Исходные Excel не загружаются в браузер.
