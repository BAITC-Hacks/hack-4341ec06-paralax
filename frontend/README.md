# Минимальный UI-каркас закупок

React + TypeScript + Vite интерфейс для сценария планирования закупок. Четыре раздела: обзор, рекомендации, черновик заказа и источники. Они используют синтетический `PlanningResult` из `src/demo/result.ts`, типизированный по `contracts/planning-result.schema.json` v0.1.0. Названия товаров и даты источников хранятся отдельно в демонстрационном `catalog`, поскольку их нет в текущем контракте.

Это **каркас**: есть навигация, поиск по позициям и просмотр кратких факторов. Расчёт, редактирование количества, утверждение и экспорт пока не подключены к новым страницам. Кнопка утверждения отключена намеренно. Существующие `planningClient.ts` и проверяемые функции демо оставлены в проекте для будущей интеграции, но этот интерфейс не обращается к API и не изменяет моковые данные.

## Запуск

Нужны Node.js 22.18+ и pnpm:

```sh
cd frontend
pnpm install
pnpm dev
```

Открыть адрес, который покажет Vite (обычно `http://127.0.0.1:5173/`). `pnpm check` запускает lint, TypeScript, существующие тесты и production build.

## Где подключать реальные данные

`src/types.ts` отражает общий контракт результата; `src/demo/result.ts` предоставляет временный набор. Страницы получают `PlanningResult` через props из `src/App.tsx`, поэтому позднее источник результата можно заменить адаптером API без переработки разметки. Не выводите название, единицу и источник остатка из SKU: согласованный контракт должен передать эти поля отдельно. Backend сейчас разрабатывается в другой ветке, а его промежуточные JSONL не являются `PlanningResult`.

Партнёрские Excel, сведения о клиентах и локальная `.analysis/` в браузер и Git не включаются. Черновик на экране не отправляется поставщику.
