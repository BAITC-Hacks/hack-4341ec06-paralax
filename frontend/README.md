# UI планирования закупок

React + TypeScript + Vite интерфейс для черновика заказа по `contracts/planning-result.schema.json` v0.1.0. Сейчас демонстрация использует только синтетический результат IEK из `src/demo/result.ts`. Партнёрские Excel и личные данные клиентов в браузер не загружаются.

## Запуск

Требуются Node.js 22.18+ и pnpm.

```sh
cd frontend
pnpm install
pnpm dev
```

Открыть `http://127.0.0.1:5174/`. `pnpm check` запускает lint, проверку типов, тесты и production сборку. Режим демонстрации работает без backend.

## Сценарий проверки

1. Нажать «Запустить расчёт». Появятся четыре синтетические рекомендации от одного поставщика IEK.
2. Открыть кабель `IEK-CAB-001`: крупная отгрузка помечена, а факторы дают `52 + 5 − 20 − 2 = 35`.
3. В предварительном сценарии увеличить товар в пути с 2 до 12: рекомендация уменьшается до 25. Это сравнение не меняет черновик.
4. Изменить выбранное количество с 35 на 42. Исходные 35 остаются видимыми.
5. Утвердить черновик, открыть раздел «Заказы» и экспортировать CSV. После перезагрузки браузера утверждённый демо-заказ доступен снова.

## Подключение backend

Задать `VITE_API_BASE_URL` в локальном `.env` и перезапустить Vite. `src/lib/planningClient.ts` использует `POST /api/planning-runs`, `PATCH /api/planning-runs/{run_id}/recommendations/{sku}`, `POST /api/planning-runs/{run_id}/approve` и `GET /api/planning-runs/{run_id}/export`. Пока серверного API нет, оставьте переменную пустой. Запрос расчёта берётся из `fixtures/planning-input.sample.json`; его потребуется заменить после выпуска контракта для реальных Excel.

UI не вычисляет количество заказа в рабочем режиме. `previewTransit` — только локальная проверка сценария на синтетическом результате. Серверный расчёт, импорт Excel и OpenAI-объяснение находятся вне текущей UI-ветки; для последнего UI пока явно показывает резервное объяснение из факторов. `catalog` содержит только подписи демо-позиций, поскольку имена, категории и источники среза отсутствуют в `PlanningResult` v0.1.0. При реальном подключении эти метаданные должны прийти через согласованный контракт, без вывода из SKU.

Утверждение в демо сохраняется в `localStorage` этого браузера и не отправляет заказ поставщику. CSV содержит поставщика, код, название, исходное и выбранное количество, статус и дату среза. Формат импорта в 1С требует отдельного согласования.
