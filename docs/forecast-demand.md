# Этап 3 — помесячный прогноз спроса

Входы — локальные JSONL этапов 1 и 2. `backend/forecast_demand.py` проверяет, что оба файла относятся к одному набору Excel: этап 2 хранит SHA-256 файла этапа 1, а результат этапа 3 сохраняет SHA-256 обоих входов. Исходные книги читаются этапом 1 из Git-коммита `a7a1d3bcd25ab137eac7915f29a4e5c2f5a0f5bc`. Общий API-контракт и `main` не меняются.

По умолчанию прогнозируются **шесть полных календарных месячных величин, сентябрь 2026 — февраль 2027**. История для модели заканчивается августом 2026. Сентябрь уже начался на дату исходного снимка 22.09.2026, поэтому в результате он помечен `current_partial_month`: прогноз относится ко **всему сентябрю**, а не только к оставшимся дням. Для следующих месяцев стоит `future_full_month`. Длительность прогноза и первый месяц настраиваются через `--months` и `--start-month`.

## Отдельные факторы

**База** — `base_demand_monthly` этапа 2 без округления.

**Тренд** считается только по `clean_demand` последних 12 полных месяцев, не по сырым продажам. Если есть профиль сезонности SKU, история предварительно делится на соответствующий индекс календарного месяца. Нужно не менее восьми известных месяцев и не менее трёх в каждой шестимесячной половине. Робастный наклон — медиана всех парных наклонов (Theil–Sen). Для применения требуются одновременно:

- сдвиг медиан первой и второй половин минимум `max(15% от базы, 1 единица)`;
- абсолютный наклон минимум `max(1% от базы, 0,1 единицы в месяц)`;
- совпадение направления сдвига медиан и наклона.

Иначе поправка нейтральна, а причина сохранена. Применённый наклон ограничен ±5% базы в месяц, суммарная поправка для любого будущего месяца — ±30% базы. В результате есть исходный и ограниченный наклон, медианы половин, месяцы наблюдений и отметка, удалось ли убрать сезонность. Если профиль сезонности недоступен, тренд может содержать сезонное движение; это ограничение видно как `neutral_no_sku_profile`.

**Сезонность** вычисляется по отдельному SKU только при **24 известных полных месяцах** и как минимум **двух годах**, в каждом из которых известно не меньше **10 месяцев**. Для года рассчитывается медианный `clean_demand`; отношение каждого месяца к этой медиане даёт годовой индекс. Индекс календарного месяца берётся как медиана отношений минимум из двух разных лет и ограничивается диапазоном 0,5–1,5. Денежные агрегированные таблицы сезонности IEK/Systeme нельзя напрямую применять к количеству SKU; они не участвуют в числовом расчёте.

База уже содержит сезонность выбранных месяцев, поэтому для будущего месяца используется отношение **индекса целевого месяца к взвешенному среднему индексу месяцев базы**. Это уменьшает риск повторного учёта сезонности. Отношение ограничено 0,5–1,5. Если данных для целевого месяца мало, коэффициент нейтрален: 1.

Для каждого будущего месяца:

`after_trend = max(0, base_demand + trend_adjustment)`

`seasonality_adjustment = after_trend × (seasonality_multiplier − 1)`

`final_forecast = after_trend + seasonality_adjustment`.

Все компоненты сохраняются отдельно. Округление до целых единиц здесь не делается; оно относится к будущему расчёту заказа. Внешний прогноз роста и срок поставки в исходниках не подтверждены, поэтому в этот этап не добавляются.

## Проверка на реальных данных

Обработаны **3 561 SKU**. Сезонность из истории SKU применена к **838**, нейтральна для **2 723**. Устойчивый рост найден у **211**, снижение — у **521** SKU. Для **554** товаров без базового спроса все шесть прогнозов равны `null`; ещё у двух товаров база равна нулю, и тренд нейтрален.

Три примера для **октября 2026**, первого полностью будущего месяца (величины в единицах товара за месяц, показаны с округлением только для чтения):

| SKU | Base demand | Trend adjustment | Seasonality adjustment | Final forecast | Причина |
| --- | ---: | ---: | ---: | ---: | --- |
| IEK `010300001_` | 12,74 | 0 | +5,60 | **18,34** | Для тренда не хватает последних месяцев; сезонность SKU доступна |
| IEK `010300002_` | 62,43 | −2,98 | −20,02 | **39,43** | Устойчивое снижение и сезонный индекс октября ниже индекса месяцев базы |
| Systeme Electric `010400433_` | 9,86 | +0,99 | +2,48 | **13,33** | Устойчивый рост и сезонный индекс октября выше индекса месяцев базы |

Это не количество к заказу. Товар в пути, актуальный остаток, lead time и страховой запас подключаются на следующих этапах. Краткая таблица и график **история clean demand → forecast** создаются для выбранного SKU; подробный JSON содержит месяцы и ссылки на исходные ячейки, годовые медианы, сезонные индексы и все проверки тренда.

## Повторить

Из корня ветки `feat/codex/backend` с установленными зависимостями:

```powershell
python -m pip install -r backend/requirements.txt
python backend/clean_demand.py
python backend/base_demand.py
python backend/forecast_demand.py --sku 010300001_ --sku 010300002_ --sku 010400433_
python -m unittest discover -s backend -p 'test_*.py' -v
```

Открыть `.analysis/forecast/iek-010300002_.html` или соседние HTML для двух других SKU. CSV содержит таблицу месячных компонентов, JSON — всю трассировку. Все 3 561 результатов лежат в `.analysis/forecast/all-skus.jsonl`. Эта папка исключена из Git, поскольку содержит производные данные партнёра.

Синтетические тесты проверяют устойчивый рост и снижение, одиночный всплеск, сезонный месяц, отсутствие двух полных лет истории, неизвестную базу, разложение прогноза на компоненты и маркировку текущего неполного месяца.
