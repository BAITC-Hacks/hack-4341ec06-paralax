# Этап 5 — дефицит

`backend/extract_balances.py` извлекает остаток и товар в пути из исходных книг, а `backend/deficit.py` сопоставляет их с необходимым запасом этапа 4 по точному ключу `(brand, sku)`. Исходные Excel читаются из неизменяемого Git-коммита `a7a1d3bcd25ab137eac7915f29a4e5c2f5a0f5bc`; книги и ветка `main` не изменяются.

## Формула и статус результата

```text
raw_deficit = target_stock − current_stock − goods_in_transit
deficit = max(0, raw_deficit)
```

`raw_deficit` сохраняет отрицательное значение, если запас и товар в пути покрывают потребность. `deficit` в этом случае равен нулю. Оба поля остаются дробными без округления: MOQ, кратность, целое количество к заказу и срочность относятся к **этапу 6**. Дефицит ещё не является рекомендацией закупки.

Если необходимый запас, актуальный остаток или товар в пути неизвестны, `raw_deficit` и `deficit` равны `null`, статус — `unavailable`. Пустая ячейка и отсутствие SKU в источнике не означают ноль; явно записанный числовой `0` остаётся нулём. Когда все три числа есть, но дата или охват баланса не подтверждены, вычисление имеет статус `provisional`. Статус `calculated` возможен только для подтверждённых текущих значений на дату планирования **со ссылками на источник обоих чисел**.

Для проверки происхождения результата сохраняются ссылки на файл, лист и ячейки исходных книг, исходный Git-коммит, SHA-256 выходов этапов 1–4 и файла балансов. Промежуточные результаты находятся только в исключённой из Git папке `.analysis/`: `.analysis/balances/source-snapshot.jsonl` и `.analysis/deficit/all-skus.jsonl`. Для выбранных SKU дополнительно создаются JSON с точными значениями и трассировкой, CSV и читаемый HTML.

## Что показывают исходные данные

У IEK сентябрьский месячный остаток означает **остаток на начало сентября**, а дата расчёта — `2026-09-23`. Движения склада между этими датами неполны, поэтому это число хранится только как `historical_stock` и **не подставляется** вместо `current_stock`. Партии товара в пути берутся из книги от 22.09.2026 с указанием исходных ячеек и сроков «поступление до»; дата и полнота партий требуют проверки. Если все шесть ячеек партий пусты, количество в пути неизвестно, а не равно нулю. Поэтому дефицит IEK на текущих исходных данных недоступен.

У Systeme Electric сводка содержит остаток в колонке `AX` и товар в пути в `BC`. Имя файла указывает `22.09.2026`, а заголовок товара в пути — `24.09`; единая дата и охват складов не подтверждены. В некоторых строках сумма складских колонок `AT:AW` расходится с `AX`. Числовой результат по таким строкам показан только как **условный** (`provisional`), пока источник не уточнён.

## Повторить самостоятельно

Из корня ветки `feat/codex/backend` установите зависимости и выполните этапы 1–4 по [инструкции этапа 4](target-stock.md), если локальных JSONL ещё нет. Для примеров выше сценарий этапа 4 запускается так:

```powershell
python backend/target_stock.py --planning-date 2026-09-23 --lead-time-days 30 --safety-stock-days 7
python backend/extract_balances.py
python backend/deficit.py --sku 010300001_ --sku 010300002_ --sku 300200851_ --sku 300200720_ --sku 010400433_
python -m unittest discover -s backend -p 'test_*.py' -v
```

Для просмотра откройте `.analysis/deficit/systeme-300200851_.html` и `.analysis/deficit/iek-010300001_.html`; рядом лежат `.json` и `.csv` с теми же именами. Полный результат по всем SKU — `.analysis/deficit/all-skus.jsonl`. Синтетические тесты проверяют арифметику, отсечение отрицательного значения, монотонность по остатку и товару в пути, неизвестное значение против числового нуля, сохранение дробей, качество источников и ошибки данных. Всего после добавления этапа 5 проходит **47 тестов**.

Позднее вместо извлечённой сводки можно подать датированный и сверенный файл JSONL через `--balances ПУТЬ`. Каждая строка содержит `(brand, sku)` и объекты `current_stock` и `goods_in_transit` с `quantity`, `quality`, `as_of_date` и `source_refs`. Для качества `confirmed_current` дата должна совпадать с датой планирования, а ссылка на источник — быть непустой. Отсутствующие SKU останутся `unavailable`; отдельный новый источник может иметь собственный `source_commit`.
