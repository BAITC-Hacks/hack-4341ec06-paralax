# Этап 2 — базовый спрос

Вход — `.analysis/clean-demand/all-skus.jsonl` этапа 1. Выход — отдельный `.analysis/base-demand/all-skus.jsonl` для каждого SKU, а для выбранных товаров также HTML, CSV и JSON. Производные данные партнёра остаются локальными и исключены из Git. Код `backend/base_demand.py` не меняет исходные Excel, `main` или общий API-контракт.

## Метод

Последний полный месяц — **август 2026**. Сентябрь 2026 отмечен этапом 1 как неполный и не участвует. Базовый спрос имеет единицу **товаров в месяц**; это ещё не прогноз на будущий месяц и не рекомендация заказа.

1. Берём шесть последних полных месяцев (март–август 2026), если у SKU есть хотя бы **4** известных `clean_demand`. В окно попадают и числовые нули. Пустота (`null`) не превращается в ноль.
2. Если известны только 0–3 месяца, расширяем окно до последних **12** полных месяцев. Нужны хотя бы **3** известных значения.
3. Иначе используем до **32** доступных полных месяцев из 2024–2026 годов, если есть хотя бы одно значение. Это исторический fallback с низкой уверенностью.
4. Если известного `clean_demand` нет вообще, `base_demand_monthly = null` и `confidence = unavailable`.

В выбранном окне исходный вес самого старого месяца — 1, следующего — 2 и так далее до N для самого нового. Пустые месяцы остаются в окне, но исключаются из суммы; веса известных месяцев нормализуются:

`base_demand_monthly = Σ(clean_demandᵢ × raw_weightᵢ) / Σ(raw_weightᵢ)`.

В JSON сохранены выбранное окно, все использованные периоды, очищенный спрос, возраст, исходный и нормализованный вес, вклад в итог, причины корректировок этапа 1 и ссылки на исходные ячейки. SHA-256 всего входного JSONL записан в результате, чтобы точно сопоставить этапы 1 и 2. Число в отчёте не округляется для последующих этапов; показ до двух знаков — только для чтения.

`confidence.score` — **эвристический показатель качества исходной истории, не вероятность точности прогноза**:

`score = history × freshness × quality × fallback`.

- `history = min(1, количество выбранных месяцев / 6)`;
- `freshness = max(0.25, 1 − 0.1 × (возраст самого свежего выбранного месяца − 1))`;
- `quality = max(0.4, 1 − (0.15×месяцы без остатка + 0.15×месяцы с вычетом выброса + 0.25×месяцы с оценкой stockout + 0.10×месяцы с отрицательным месячным итогом) / число выбранных месяцев)`;
- `fallback`: 1 для 6 месяцев, 0.75 для 12, 0.5 для исторического окна.

Категории: `high` при score ≥ 0.8, `medium` при score ≥ 0.5, иначе `low`; без истории — `unavailable`. Факторы и машинные причины сохраняются отдельно. Это рабочие допущения MVP; для бизнес-применения пороги следует откалибровать на проверенной истории.

## Проверка на реальных данных

Обработаны **3 561 SKU**: основной шестимесячный расчёт — **1 238**, 12-месячный fallback — **679**, исторический fallback — **1 090**, нет релевантной истории — **554**. Уверенность: high — 948, medium — 670, low — 1 389, unavailable — 554.

| SKU | Метод и использованные месяцы | Пример весов | Базовый спрос, ед./мес. | Уверенность |
| --- | --- | --- | ---: | --- |
| IEK `010300001_` | 12 месяцев; 8 известных из сент. 2025–авг. 2026 | сент. 2025: 1/39; июнь 2026: 10/39 | **12,74** | medium, 0,59 |
| IEK `010300002_` | 6 месяцев, март–август 2026 | март: 1/21; август: 6/21 | **62,43** | high, 0,95 |
| Systeme Electric `010400433_` | 6 месяцев, март–август 2026 | март: 1/21; август: 6/21 | **9,86** | high, 0,95 |

Например, для IEK `010300002_` использованы очищенные значения **145, 37, 53, 71, 29, 84** с весами **1, 2, 3, 4, 5, 6**. Проверка: `(145×1 + 37×2 + 53×3 + 71×4 + 29×5 + 84×6) / 21 = 62,428571…`. Два из этих месяцев уже скорректированы на этапе 1; исходные документы видны в его JSON-трассировке.

## Повторить

Из корня ветки `feat/codex/backend`:

```powershell
python -m pip install -r backend/requirements.txt
python backend/clean_demand.py
python backend/base_demand.py --sku 010300001_ --sku 010300002_ --sku 010400433_
python -m unittest discover -s backend -p 'test_*.py' -v
```

Открыть `.analysis/base-demand/iek-010300002_.html` или соседние файлы для двух других SKU. CSV показывает периоды, значения и веса; JSON дополнительно содержит confidence и ссылки на исходные ячейки. Для любого другого товара передать его код через `--sku`; если код совпадает у брендов, добавить `--brand IEK` либо `--brand "Systeme Electric"`.

Синтетические тесты проверяют возрастающие веса, нормализацию при пропусках, оба fallback, отсутствие выдуманного нуля, исключение неполного месяца и снижение confidence при корректировках.
