# Подготовка данных — akzhan

Это стартовая часть backend для работы с Excel из ТЗ по заказам поставщикам.
Сейчас она хранит список 12 ожидаемых файлов и проверяет, доступны ли они.
Проверка наличия не означает, что таблицы прочитаны или подходят для расчёта.

## Запуск из корня проекта

```powershell
python -m backend.importers
python -m backend.importers --data-dir "C:\path\to\data"
```

Достаточно Python 3.11 или новее; эта команда использует только стандартную библиотеку.
Внутри папки данных ожидаются `IEK/` и `Systeme electric/` с файлами из репозитория.
Команда выводит каждый файл, его назначение и итог. Код завершения `0` — все файлы
найдены, `1` — хотя бы один отсутствует. Исходные книги не изменяются.

## Дерево этой части

```text
backend/importers/
  __init__.py   — пакет подготовки данных
  sources.py    — список файлов по брендам и назначению
  __main__.py   — команда проверки наличия
  README.md     — инструкция и ближайшие шаги
```

## Следующий небольшой шаг

1. Сопоставить колонки продаж, остатков и товара в пути IEK по коду 1С.
2. Согласовать с владельцем основного backend формат передачи этих данных.
3. Добавить чтение одного источника и проверку нескольких товаров.

Код товара сохраняется строкой, включая завершающий `_`. Знаки количества и
пустые ячейки требуют отдельного правила: их нельзя автоматически заменять нулями.
Месячный остаток имеет свою дату; он не обязательно отражает сегодняшний склад.
Для связывания файлов нельзя использовать одно только название товара.

Текущая входная схема в `contracts/` требует поля, которых нет в Excel (например,
ID клиента). До её согласования этот пакет не формирует `PlanningInput` и не
подставляет придуманные значения. Расчёт заказов, HTTP API и объяснения AI пока
не реализованы в этой части. Уже существующий разбор таблиц в ветке
`feat/codex/backend` можно использовать как справочный материал после сверки.

## Разделение работы

- akzhan: исходные таблицы и подготовка данных в `backend/importers/`.
- Участник интерфейса: `frontend/`.
- Участник основного backend: сервер и подключение подготовленных данных.

Имена двух других участников и владельцев расчёта/AI ещё нужно записать в
`docs/tasks.md`. Общие схемы и чужие рабочие ветки согласуются отдельно.
